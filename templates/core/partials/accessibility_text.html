1. Our Commitment

At recipe.klopot.tech ("Shoppin," "the Service," "we," "us," or "our"), we believe culinary management, meal planning, and grocery shopping should be accessible, inclusive, and barrier-free for everyone, including individuals with visual, auditory, motor, cognitive, or neurological disabilities.

We are dedicated to continually auditing, improving, and optimizing the accessibility of our web platform to adhere to internationally recognized standards and ensure that every user can independently browse recipes, plan meals, manage pantry staples, and execute in-store shopping trips.

2. Conformance Status & Standards

The Web Content Accessibility Guidelines (WCAG) define technical requirements for designers and developers to improve web accessibility for people with disabilities. It defines three levels of conformance: Level A, Level AA, and Level AAA.

recipe.klopot.tech is designed and actively audited to conform with WCAG 2.1 and WCAG 2.2 Level AA standards.

3. Accessibility Measures & Features Implemented

We have integrated accessibility directly into the architecture, design systems, and interaction patterns of Shoppin:

  • Visual Contrast & Boundary Visibility (WCAG 1.4.3 & 1.4.11): Body text and interactive labels maintain a contrast ratio of at least 4.5:1 against light backgrounds (with standard text achieving a 9.0:1 ratio). All interactive controls, quick-action buttons (Got, Need, Have, Skip), form fields, and checkboxes feature visual boundaries with at least a 3:1 luminosity contrast ratio (border-gray-400).
  • Accessible Names & Label in Name (WCAG 2.5.3): All interactive buttons, quick toggles, and modal controls have accessible names that match or begin with their visually presented text, ensuring seamless voice-control and screen-reader usability.
  • Keyboard Navigation & Focus Indicators (WCAG 2.1.1 & 2.4.7): All application functions are fully operable via a keyboard without requiring a mouse. High-contrast focus rings (focus-visible:ring-2 focus-visible:ring-gray-900) clearly delineate the currently focused element. A skip link is provided at the top of every page to bypass repetitive navigation landmarks.
  • Keyboard Drag-and-Drop Alternative (WCAG 2.1.1 & 2.5.7): In addition to touch and mouse drag-and-drop reordering, all shopping list and category drag handles are keyboard focusable (role="button" tabindex="0"). Users can reorder items and sections directly using the Alt+ArrowUp and Alt+ArrowDown hotkeys.
  • Live Regions & Dynamic Hypermedia Notifications (WCAG 4.1.2 & 4.1.3): Real-time WebSocket and HTMX toast notifications are announced via an ARIA live region (aria-live="polite"), informing assistive technology users of cart and status updates without interrupting active reading flow.
  • Modal Dialog Trapping & ARIA Semantics (WCAG 1.3.1 & 4.1.2): Modal overlays (store picker, recipe editor, workspace settings) utilize standard WAI-ARIA dialog specifications (role="dialog" aria-modal="true") with proper heading labels, keyboard focus traps, and Escape key dismissal.
  • Input Purpose & Autocomplete (WCAG 1.3.5): Form inputs feature standard HTML5 input types and browser autocomplete attributes to assist users with password managers, screen magnifiers, and assistive autofill technology.
  • Text Resizing & Responsive Layout (WCAG 1.4.4 & 1.4.10): The interface supports browser zoom up to 200% without horizontal scroll traps, clipping, or loss of content. CSS media queries honor user preferences for reduced motion (prefers-reduced-motion).
  • Non-Text Content & Map Pins (WCAG 1.1.1): Informational images include descriptive alternative text (alt="..."). Purely decorative elements and dynamic Leaflet GPS map markers are explicitly designated as aria-hidden="true" to prevent auditory clutter for screen-reader users.

4. Technical Specifications

The accessibility of recipe.klopot.tech relies on the following technologies to work with user web browsers and assistive technologies or plugins installed on your computer:

  • HTML5 Semantic Landmarks (<nav>, <main>, <footer>, <header>)
  • WAI-ARIA (Accessible Rich Internet Applications) 1.2
  • CSS3 / Modern Tailwind CSS
  • JavaScript & HTMX 2.0

5. Assessment & Testing Methodology

We test recipe.klopot.tech through multiple evaluation methods:

  • Automated Accessibility Scanning: Regular scans using industry-standard tools (including AudioEye and axe-core) to identify contrast, attribute mismatches, and semantic defects.
  • Fine-Grained DOM Inspections: Automated testing scripts verifying heading hierarchy, ARIA label consistency, and form control associations.
  • Manual Keyboard & Assistive Tech Testing: Testing without a mouse across desktop and mobile browsers, validating focus order, tab sequence, and screen-reader announcements.

6. Known Limitations & Third-Party Content

Despite our rigorous efforts to ensure accessibility across all pages, there may be temporary limitations in specific contexts:

  • User-Submitted Recipe Photography & Notes: Community-submitted or externally imported recipes may reference photographs or descriptions provided by third-party authors where descriptive alt text is limited.
  • Third-Party Geolocation Map Tiles: When using the "Near Me" supermarket store locator, interactive map tiles are provided by OpenStreetMap / Leaflet. While store selection controls and lists are fully accessible, the interactive visual map tile canvas may be difficult to navigate with screen readers; all store choices and details remain accessible via standard text lists.
